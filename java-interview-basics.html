Introduction to Java

Java is a high-level, object-oriented, platform-independent programming language created by James Gosling at Sun Microsystems in 1995. The key philosophy: "Write Once, Run Anywhere" (WORA) — you write Java code once and it runs on any device that has a JVM.

📅

Year Born

Released in 1995. Originally called "Oak", later renamed Java.

🌐

Platform Independent

Compiles to bytecode that runs on any OS with JVM installed.

🏢

Widely Used

Used in Android apps, banking systems, enterprise software, and more.

🛡️

Strongly Typed

Every variable must be declared with a type. Prevents many bugs.

JAVA — Hello World
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!"); // Output: Hello, World!
    }
}
⚡ Interview Point
  • Java is not 100% object-oriented because it has primitive data types (int, char, etc.)
  • Java is compiled AND interpreted — source code → bytecode (compiler) → machine code (JVM)

JVM, JRE, and JDK

🧠 Real World Analogy

Think of it like a car: JVM = the engine, JRE = the full car (engine + body), JDK = the full car + the factory to build more cars.

ComponentFull NameWhat It DoesWho Needs It
JVMJava Virtual MachineExecutes bytecode on your machineEveryone running Java
JREJava Runtime EnvironmentJVM + libraries needed to run Java appsEnd users running Java apps
JDKJava Development KitJRE + compiler + debugging toolsDevelopers writing Java code

📦 Containment Relationship

JDK ⊇ JRE ⊇ JVM — The JDK contains everything. Install JDK when you're developing, JRE when you're just running.

⚡ Interview Point

JVM is platform-dependent (different JVM for Windows, Mac, Linux), but Java bytecode is platform-independent. That's the WORA magic.

04

How Java Works

Step-by-Step Execution

  1. Write: You write .java source code
  2. Compile: javac compiler converts it to .class bytecode
  3. Load: ClassLoader loads the bytecode into JVM
  4. Verify: Bytecode verifier checks for security issues
  5. Execute: JVM interprets bytecode (or JIT compiles it to native code)
TERMINAL — Compile & Run
# Step 1: Compile Java source to bytecode
javac HelloWorld.java      # Creates HelloWorld.class

# Step 2: Run using JVM
java HelloWorld            # Output: Hello, World!

Conditional Statements

JAVA — if-else & switch
int marks = 85;

// if-else chain
if (marks >= 90) {
    System.out.println("Grade A+");
} else if (marks >= 80) {
    System.out.println("Grade A");  // ← This runs
} else {
    System.out.println("Grade B");
}

// switch — best for fixed discrete values
int day = 3;
switch (day) {
    case 1: System.out.println("Monday"); break;
    case 2: System.out.println("Tuesday"); break;
    case 3: System.out.println("Wednesday"); break; // ← Runs
    default: System.out.println("Other");
}
⚠️ Watch Out

Always use break in switch cases to avoid fall-through (executing subsequent cases unintentionally).

Loops

JAVA — All Loop Types
// 1. for loop — when you know the count
for (int i = 0; i < 5; i++) {
    System.out.print(i + " "); // 0 1 2 3 4
}

// 2. while loop — when condition-based
int n = 1;
while (n <= 5) {
    System.out.print(n + " "); // 1 2 3 4 5
    n++;
}

// 3. do-while — runs at LEAST once
int x = 10;
do {
    System.out.println("Runs once even if false!");
    x++;
} while (x < 5); // condition false but runs once

// 4. Enhanced for loop (for-each)
int[] nums = {1, 2, 3, 4, 5};
for (int num : nums) {
    System.out.print(num + " ");
}

Arrays

An array stores a fixed-size collection of elements of the same type. Index starts at 0.

🔑 Analogy: A row of numbered mailboxes — each box holds one letter and is identified by its number.

JAVA — Arrays
// Declaration and initialization
int[] nums = {10, 20, 30, 40, 50};

// Access by index
System.out.println(nums[0]);  // 10
System.out.println(nums[4]);  // 50
System.out.println(nums.length); // 5

// 2D Array (matrix)
int[][] matrix = {{1,2},{3,4},{5,6}};
System.out.println(matrix[1][0]); // 3

// Useful: Arrays.sort()
java.util.Arrays.sort(nums);  // sorts in-place
⚡ Interview Point

Arrays are fixed-size. If you need dynamic resizing, use ArrayList. Arrays can cause ArrayIndexOutOfBoundsException if you access an invalid index.

JAVA — String vs StringBuilder
// String — immutable, thread-safe
String s1 = "Hello";
String s2 = s1 + " World"; // New object created

// StringBuilder — mutable, faster for concatenation
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World");        // Modifies in place — efficient
System.out.println(sb.toString()); // Hello World

// == vs equals() — VERY important!
String a = "Java";
String b = "Java";
String c = new String("Java");
System.out.println(a == b);       // true  (same pool reference)
System.out.println(a == c);       // false (different object)
System.out.println(a.equals(c));  // true  (same content)
⚡ Interview Point
  • Always use .equals() to compare String content, NOT ==
  • String is stored in the String Pool (heap memory optimization)
  • StringBuilder (not thread-safe) is faster than StringBuffer (thread-safe)

Class and Object

Class = Blueprint (e.g., car design). Object = Instance (e.g., an actual car built from that design). You can create many objects from one class.

JAVA — Class and Object
// Class definition = blueprint
class Car {
    String brand;   // Instance variable (attribute)
    int speed;

    void drive() { // Method (behavior)
        System.out.println(brand + " driving at " + speed + " km/h");
    }
}

public class Main {
    public static void main(String[] args) {
        Car myCar = new Car();  // Object created using 'new'
        myCar.brand = "Toyota";
        myCar.speed = 120;
        myCar.drive(); // Toyota driving at 120 km/h
    }
}
13

Encapsulation

Make fields private and expose them through public getters/setters. This gives controlled access and protects data integrity.

JAVA — Encapsulation
class BankAccount {
    private double balance;  // Hidden from outside

    public double getBalance() {
        return balance;      // Controlled read
    }

    public void deposit(double amount) {
        if (amount > 0) balance += amount;  // Validated write
    }
}
⚡ Interview Point

Encapsulation achieves data hiding. Benefits: security, flexibility to change implementation, validation in setters. A fully encapsulated class is called a POJO (Plain Old Java Object).

14

Inheritance

JAVA — Inheritance Types
// Parent (Super) class
class Animal {
    String name;
    void eat() { System.out.println(name + " is eating"); }
}

// Child (Sub) class — single inheritance
class Dog extends Animal {
    void bark() { System.out.println(name + " says: Woof!"); }
}

class Labrador extends Dog {  // Multi-level inheritance
    void fetch() { System.out.println("Fetching!"); }
}

// Usage
Labrador lab = new Labrador();
lab.name = "Bruno";
lab.eat();   // Inherited from Animal
lab.bark();  // Inherited from Dog
lab.fetch(); // Own method
⚡ Interview Point
  • Java supports Single, Multi-level, and Hierarchical inheritance
  • Java does NOT support multiple inheritance with classes (to avoid Diamond Problem)
  • Multiple inheritance is achieved using Interfaces

Abstraction

JAVA — Abstract Class
abstract class Vehicle {
    String brand;

    abstract void startEngine();   // No body — must implement in child

    void showBrand() {              // Concrete method — has body
        System.out.println("Brand: " + brand);
    }
}

class Bike extends Vehicle {
    @Override
    void startEngine() { System.out.println("Bike engine started 🏍️"); }
}

// Vehicle v = new Vehicle(); // ERROR! Can't instantiate abstract class
Vehicle v = new Bike();
v.startEngine(); // "Bike engine started 🏍️"
⚡ Interview Point
  • Abstract class can have both abstract and concrete methods
  • You cannot instantiate an abstract class
  • A class with even one abstract method must be declared abstract
17

Constructor Types

A constructor is a special method called when an object is created. It has the same name as the class and no return type.

JAVA — Constructor Types
class Student {
    String name;
    int age;

    // 1. Default Constructor (no parameters)
    Student() {
        name = "Unknown";
        age = 0;
    }

    // 2. Parameterized Constructor
    Student(String name, int age) {
        this.name = name;  // 'this' refers to current object
        this.age = age;
    }

    // 3. Copy Constructor
    Student(Student s) {
        this.name = s.name;
        this.age = s.age;
    }
}

Student s1 = new Student();             // Default
Student s2 = new Student("Deepak", 21); // Parameterized
Student s3 = new Student(s2);           // Copy
⚡ Interview Point

If you don't define any constructor, Java provides a default constructor automatically. Once you define a parameterized constructor, the default one is no longer provided automatically.

Static Keyword

JAVA — static variables, methods, blocks
class Counter {
    static int count = 0;  // Shared by all objects
    String name;

    static {  // Static block — runs once when class loads
        System.out.println("Counter class initialized");
    }

    Counter(String name) {
        this.name = name;
        count++;  // Shared across all instances
    }

    static int getCount() {  // Static method — no 'this'
        return count;
    }
}

new Counter("A");
new Counter("B");
System.out.println(Counter.getCount()); // 2
⚡ Interview Point
  • Static members belong to the class, not to any object
  • Static methods cannot access instance variables or use this/super
  • Call static members using class name: ClassName.method()

Method Overloading vs Overriding

Method Overloading

  • Same method name, different parameters
  • In the same class
  • Compile-time polymorphism
  • Return type can differ
  • No inheritance needed
VS

Method Overriding

  • Same method name AND parameters
  • In parent-child classes
  • Runtime polymorphism
  • Same return type (or covariant)
  • Requires inheritance
JAVA — Overloading vs Overriding
// OVERLOADING — same class, different params
class Calculator {
    int    add(int a, int b)    { return a + b; }
    double add(double a, double b) { return a + b; }
    int    add(int a, int b, int c) { return a+b+c; }
}

// OVERRIDING — parent-child, same signature
class Animal {
    void sound() { System.out.println("Some sound"); }
}
class Cat extends Animal {
    @Override
    void sound() { System.out.println("Meow 🐱"); }
}

Interface vs Abstract Class

Interface

  • 100% abstract (by default)
  • Multiple implementation allowed
  • All methods public by default
  • No constructors
  • Use: implements
  • Variables are public static final
VS

Abstract Class

  • Partial abstraction possible
  • Single inheritance only
  • Any access modifier
  • Can have constructors
  • Use: extends
  • Variables can be any type
JAVA — Interface Example
interface Flyable {
    void fly();                       // abstract by default
    default void land() {            // default method (Java 8+)
        System.out.println("Landing...");
    }
}
interface Swimmable { void swim(); }

// Multiple interfaces — solving diamond problem!
class Duck implements Flyable, Swimmable {
    public void fly()  { System.out.println("Duck flying 🦆"); }
    public void swim() { System.out.println("Duck swimming 🏊"); }
}

Exception Handling

An exception is an unexpected event that disrupts normal program flow. Java provides a structured way to handle them using try-catch-finally.

🔑 Analogy: Like a safety net — if an acrobat (program) falls (exception), the net (catch) prevents disaster.

TypeExamplesMust Handle?
Checked ExceptionIOException, SQLException, FileNotFoundExceptionYes (compile-time)
Unchecked ExceptionNullPointerException, ArrayIndexOutOfBoundsException, ArithmeticExceptionNo (runtime)
ErrorStackOverflowError, OutOfMemoryErrorNo (JVM level)
JAVA — try-catch-finally + custom exception
public class ExceptionDemo {
    public static void main(String[] args) {
        try {
            int result = 10 / 0;  // ArithmeticException!
        } catch (ArithmeticException e) {
            System.out.println("Caught: " + e.getMessage());
        } catch (Exception e) {
            System.out.println("Generic: " + e.getMessage());
        } finally {
            System.out.println("Always runs!"); // Cleanup here
        }
    }
}

// Custom Exception
class AgeException extends RuntimeException {
    AgeException(String msg) { super(msg); }
}
// throw new AgeException("Age must be positive!");
⚡ Interview Point
  • throw = manually throw an exception; throws = declare that a method may throw
  • finally block always executes, even if no exception occurs or return is used
  • Use multi-catch (Java 7+): catch (IOException | SQLException e)

ArrayList vs LinkedList

ArrayList

  • Dynamic array internally
  • Fast random access O(1)
  • Slow insert/delete mid O(n)
  • Less memory
  • Best for: frequent reads
VS

LinkedList

  • Doubly-linked list internally
  • Slow random access O(n)
  • Fast insert/delete O(1)
  • More memory (node pointers)
  • Best for: frequent inserts

HashMap Basics

HashMap stores key-value pairs. Keys are unique; values can repeat. Average O(1) for get/put. Not thread-safe.

🔑 Analogy: A dictionary — you look up a word (key) to get its meaning (value).

JAVA — HashMap
import java.util.*;

HashMap<String, Integer> scores = new HashMap<>();
scores.put("Alice", 95);
scores.put("Bob",   87);
scores.put("Alice", 98);  // Overwrites Alice's old value

System.out.println(scores.get("Bob"));       // 87
System.out.println(scores.containsKey("Alice")); // true
System.out.println(scores.size());            // 2

// Iterate over entries
for (Map.Entry<String, Integer> e : scores.entrySet()) {
    System.out.println(e.getKey() + " → " + e.getValue());
}

Multithreading Basics

A thread is the smallest unit of execution. Multithreading allows multiple threads to run concurrently, improving performance on multi-core processors.

🔑 Analogy: A restaurant with multiple waiters (threads) serving customers (tasks) simultaneously.

JAVA — Creating Threads (2 ways)
// Way 1: Extend Thread class
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread running: " + Thread.currentThread().getName());
    }
}
MyThread t = new MyThread();
t.start(); // Never call run() directly — use start()

// Way 2: Implement Runnable (Preferred — avoids extends lock)
class Task implements Runnable {
    public void run() { System.out.println("Task running!"); }
}
Thread t2 = new Thread(new Task());
t2.start();

// Thread states: NEW → RUNNABLE → RUNNING → WAITING → TERMINATED
29

Synchronization

When multiple threads access shared resources, synchronization prevents data corruption by ensuring only one thread executes a synchronized block at a time.

🔑 Analogy: One toilet stall (shared resource) with a lock — only one person (thread) can use it at a time.

JAVA — synchronized keyword
class Counter {
    private int count = 0;

    // synchronized method — only one thread at a time
    public synchronized void increment() {
        count++;
    }

    public int getCount() { return count; }
}

// Without synchronized, concurrent increments cause race conditions!
// With synchronized, count is always accurate.
⚡ Interview Point
  • Race condition: Two threads access shared data simultaneously, causing incorrect results
  • Deadlock: Two threads wait for each other's lock forever
  • Use volatile keyword for visibility; use synchronized for atomicity
30

Garbage Collection

Java automatically manages memory. The Garbage Collector (GC) removes objects from heap memory that are no longer referenced, preventing memory leaks.

🔑 Analogy: A municipal garbage truck that automatically collects trash (unused objects) you've left out.

JAVA — GC & finalize
class Demo {
    @Override
    protected void finalize() {  // Called before GC (deprecated in Java 9)
        System.out.println("Object being garbage collected");
    }
}

Demo d = new Demo();
d = null;              // Object now eligible for GC
System.gc();           // Request GC (not guaranteed)
⚡ Interview Point
  • GC runs in the background — you can't control exactly when
  • Objects become eligible when there are no more references pointing to them
  • Java uses Mark-and-Sweep algorithm — mark live objects, sweep (delete) unmarked ones

Lambda Expressions

Lambda expressions provide a way to write anonymous functions inline. Syntax: (parameters) -> expression

JAVA — Lambda Expressions
import java.util.*;

// Before Java 8 (verbose)
Runnable r1 = new Runnable() {
    public void run() { System.out.println("Old way"); }
};

// With Lambda (clean!)
Runnable r2 = () -> System.out.println("Lambda way");

// Sorting with lambda
List<String> names = Arrays.asList("Charlie", "Alice", "Bob");
names.sort((a, b) -> a.compareTo(b));
System.out.println(names); // [Alice, Bob, Charlie]

// Arithmetic with functional interface

public static boolean isPrime(int n) {
    if (n <= 1) return false;
    for (int i = 2; i <= Math.sqrt(n); i++) {
        if (n % i == 0) return false;
    }
    return true;
}

// Iterative
public static long factorial(int n) {
    long result = 1;
    for (int i = 2; i <= n; i++) result *= i;
    return result;
}
// Recursive version:
public static long factRec(int n) {
    return (n <= 1) ? 1 : n * factRec(n - 1);
}
// factorial(5) → 120

📊 Bubble Sort

JAVA
public static void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int i = 0; i < n-1; i++) {
        for (int j = 0; j < n-i-1; j++) {
            if (arr[j] > arr[j+1]) {
                int t = arr[j]; arr[j] = arr[j+1]; arr[j+1] = t;
            }
        }
    }
}
// {5,3,8,1} → {1,3,5,8}  O(n²)

Common Interview Questions & Answers

Q: What is the difference between == and .equals() in Java? ▼
== compares references (memory addresses). .equals() compares content/values. For strings, always use .equals() unless you intentionally want reference comparison. Example: new String("a") == new String("a") is false, but .equals() returns true.
Q: What is the difference between abstract class and interface? ▼
Abstract class: can have state (fields), constructors, concrete methods, any access modifiers. Use when related classes share implementation. Interface: only constants and abstract methods (before Java 8), supports multiple implementation. Use to define a contract/capability. Key rule: a class can implement multiple interfaces but extend only one abstract class.
Q: What is the difference between String, StringBuilder, and StringBuffer? ▼
String: Immutable, thread-safe, stored in String Pool. StringBuilder: Mutable, NOT thread-safe, fast — use for single-thread string manipulation. StringBuffer: Mutable, thread-safe (synchronized), slower — use in multi-threaded environments. For heavy concatenation in loops, always use StringBuilder.
Q: What is a NullPointerException and how to avoid it? ▼
NPE occurs when you try to use a reference that is null (e.g., calling a method on null object). Avoid by: checking if (obj != null) before use, using Java 8's Optional, using Objects.requireNonNull(), initializing variables properly, or using the safe navigation pattern.
Q: What is the difference between ArrayList and LinkedList? ▼
ArrayList uses a dynamic array internally — fast random access O(1) but slow insertion/deletion in middle O(n). LinkedList uses doubly-linked nodes — fast insertion/deletion O(1) but slow random access O(n). Use ArrayList for read-heavy operations, LinkedList for frequent add/remove at head or middle.
Q: What is method overloading vs overriding? ▼
Overloading: Same method name, different parameter list in same class. Resolved at compile-time (static binding). Overriding: Subclass redefines a method from parent class with same signature. Resolved at runtime (dynamic binding). Overriding requires @Override annotation (recommended) and the method in parent must not be private/static/final.
Q: What is a constructor? Can it be private? ▼
A constructor is a special method invoked when an object is created. It has the class name and no return type. Yes, it can be private — used in the Singleton design pattern to prevent external instantiation. A private constructor means only the class itself can create its instance.
Q: What is the purpose of the 'final' keyword? ▼
final variable: constant — value cannot be changed after assignment. final method: cannot be overridden in subclass. final class: cannot be subclassed (inherited). Example: String is a final class, making it immutable. Use final to create constants: static final double PI = 3.14;
Q: Explain try-with-resources (Java 7+) ▼
Try-with-resources automatically closes resources (files, DB connections) that implement AutoCloseable. Syntax: try (FileReader fr = new FileReader("file.txt")) { ... }. The resource is automatically closed when the try block exits, even if an exception occurs. Eliminates verbose finally blocks for cleanup.
Q: What is the Java Collections hierarchy? ▼
Root: Iterable interface. Collection extends Iterable: → List (ArrayList, LinkedList, Vector) → Set (HashSet, TreeSet, LinkedHashSet) → Queue (LinkedList, PriorityQueue). Separate: Map interface (HashMap, TreeMap, LinkedHashMap, Hashtable). Note: Map does NOT extend Collection.
Q: What is the difference between HashMap and Hashtable? ▼
HashMap: Not thread-safe, allows one null key and multiple null values, faster, introduced in Java 1.2. Hashtable: Thread-safe (synchronized), does NOT allow null keys or values, slower, legacy class from Java 1.0. In modern code, prefer ConcurrentHashMap over Hashtable for thread safety.
Q: What are Java 8 Stream API operations? ▼
Two types: Intermediate (lazy, return Stream): filter(), map(), flatMap(), sorted(), distinct(), limit(), skip(). Terminal (trigger execution, return result): collect(), forEach(), count(), reduce(), findFirst(), anyMatch(), allMatch(), toArray(). Streams are lazy — intermediate operations only run when a terminal operation is called.
